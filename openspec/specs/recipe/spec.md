# recipe Specification

## Purpose

レシピを扱う capability。ユーザーが登録した料理レシピの一覧・検索・詳細参照・登録編集を提供する。
本 proposal では「一覧の表示・検索・ソート」と「新規レシピボタンの配置」までを扱い、詳細ドロワー・
登録編集・SQLite 永続化は後続 proposal で追加する。

## Requirements

### Requirement: レシピ一覧の初期表示

システムは、S02 レシピ一覧を開いたとき、登録済みレシピをテーブル形式で一覧表示 SHALL する。
テーブルの列は「名前 / タグ / 更新日」の 3 列であり、1 レシピにつき 1 行を表示する。
初期ソートは「更新日 降順 (更新が新しいものが上)」とする。

#### Scenario: レシピが 1 件以上ある場合はテーブルに並ぶ

- **WHEN** ユーザーが S02 レシピ一覧を開く
- **THEN** テーブルヘッダに「名前」「タグ」「更新日」の 3 列が表示される
- **AND** 登録されているレシピが 1 行 1 レシピで並ぶ
- **AND** 行は更新日の降順 (新しいものが上) で並んでいる

#### Scenario: 1 レシピに複数タグがある場合はまとめて表示される

- **WHEN** ユーザーが S02 を開き、複数タグを持つレシピの行を見る
- **THEN** タグ列にそのレシピのタグがすべて視認できる形で表示される (区切り文字や折返しはワイヤーに従う)

#### Scenario: レシピが 0 件の場合は空状態を示す

- **WHEN** ユーザーが S02 を開き、登録済みレシピが 1 件も無い
- **THEN** テーブル本体の代わりに「まだレシピが登録されていない」旨のメッセージが表示される

### Requirement: レシピ名検索

システムは、画面上部の検索欄を SHALL 提供する。ユーザーがテキストを入力すると、レシピ名の部分一致に該当するレシピだけが
テーブルに残り、該当しないレシピは表示から除外される。検索は大文字小文字を区別せず、一覧取得の再問い合わせは伴わない。

#### Scenario: 検索語がレシピ名に部分一致する

- **WHEN** ユーザーが検索欄にレシピ名の一部を入力する
- **THEN** レシピ名にその文字列を含むレシピのみがテーブルに表示される
- **AND** 一致しないレシピは表示から除外される

#### Scenario: 検索語が空になる

- **WHEN** ユーザーが検索欄を空にする
- **THEN** テーブルには絞り込み前の全レシピが再表示される

#### Scenario: 検索語がどのレシピにも一致しない

- **WHEN** ユーザーが検索欄にどのレシピ名にも含まれない文字列を入力する
- **THEN** テーブルには 1 件も表示されず、「一致するレシピがない」旨のメッセージが表示される

### Requirement: ソート切替

システムは、ユーザーがテーブルの並び順を「更新日 降順」と「名前 昇順」の 2 種類から選べる UI を SHALL 提供する。
既定は「更新日 降順」。切替は表示順のみに影響し、サーバから受け取るデータ範囲には影響しない。

#### Scenario: 初期状態は更新日 降順

- **WHEN** ユーザーが S02 を開く
- **THEN** ソート選択の初期値が「更新日 降順」になっている
- **AND** テーブル行が更新日の新しい順に並んでいる

#### Scenario: 名前 昇順に切り替える

- **WHEN** ユーザーがソート選択を「名前 昇順」に変更する
- **THEN** テーブル行がレシピ名の昇順で並び替わる

#### Scenario: ソートは検索フィルタと併用できる

- **WHEN** ユーザーが検索欄に文字列を入力した上で「名前 昇順」に切り替える
- **THEN** 検索で絞り込まれたレシピが、名前 昇順で並んで表示される

### Requirement: 「新しいレシピ」ボタンから S04 新規登録画面への遷移

システムは、S02 レシピ一覧右上の「新しいレシピ」ボタンが押されたとき、S04 レシピ登録画面 (新規モード) に SHALL 遷移する。
遷移先の画面は「新しいレシピ」であることが分かるタイトル表示を持ち、入力欄は初期値なしの状態で開かれる。

#### Scenario: ボタンを押すと S04 新規登録画面に遷移する

- **WHEN** ユーザーが「新しいレシピ」ボタンを押す
- **THEN** 画面が S04 レシピ登録画面 (新規モード) に遷移する
- **AND** 名前 / 人数 / タグ / 材料 / 手順 / メモの入力欄が初期値なしで表示される

### Requirement: S02 一覧からのレシピ編集導線 (暫定)

システムは、S02 レシピ一覧の各行を押下できるようにし、押下したレシピの S04 編集画面へ遷移する導線を SHALL 提供する。
本要件は S03 レシピ詳細ドロワーが未実装の期間の暫定であり、詳細ドロワー導入時点で「行押下 → S03 → 編集ボタン → S04」の導線に置き換わる。

#### Scenario: 行を押下すると当該レシピの編集画面に遷移する

- **GIVEN** レシピ「肉じゃが」が S02 レシピ一覧に表示されている
- **WHEN** ユーザーが「肉じゃが」の行を押下する
- **THEN** 画面が S04 レシピ編集画面に遷移し、「肉じゃが」の既存値がロードされている

### Requirement: レシピの新規登録

システムは、S04 レシピ登録画面を新規モードで開いた際、名前 / 人数 / タグ / 材料 / 手順 / メモを入力して保存できることを SHALL 保証する。
保存に成功したレシピは以降 S02 レシピ一覧の対象に含まれ、アプリを再起動しても保持される。名前は必須項目であり、空のままでは保存できない。
材料 0 件・手順 0 字・タグ 0 件は許容する (登録の途中保存を妨げないため)。

#### Scenario: 名前と最小限の内容だけで新規レシピを保存する

- **GIVEN** ユーザーが S02 で「＋ 新しいレシピ」ボタンを押して S04 新規登録画面を開いている
- **WHEN** ユーザーが名前に「肉じゃが」を入力し、他の欄は空のまま「保存」を押す
- **THEN** レシピが保存される
- **AND** 画面は S02 レシピ一覧に戻る
- **AND** S02 の一覧に「肉じゃが」の行が追加されている

#### Scenario: 材料に自由テキストを入れてレシピを登録する

- **GIVEN** ユーザーが S04 新規登録画面を開いている
- **WHEN** ユーザーが名前に「肉じゃが」、人数に「2」を入力する
- **AND** 材料行の名前欄に「玉ねぎ」、量欄に「1」、単位欄に「個」を入力する
- **AND** ユーザーが「保存」を押す
- **THEN** レシピが保存される
- **AND** 画面は S02 レシピ一覧に戻る
- **AND** 追加されたレシピが目印 (ハイライト等) 付きで識別できる

#### Scenario: 名前が空のままでは保存できない

- **GIVEN** ユーザーが S04 新規登録画面を開いている
- **WHEN** ユーザーが名前欄を空のまま「保存」を押す
- **THEN** 保存は行われず、名前欄に必須項目である旨のエラー表示が出る
- **AND** 画面は S04 新規登録画面のままである

#### Scenario: 保存したレシピはアプリ再起動後も残る

- **GIVEN** ユーザーが S04 で「肉じゃが」を保存した
- **WHEN** アプリを終了して再起動し、S02 レシピ一覧を開く
- **THEN** 一覧に「肉じゃが」が引き続き表示される

### Requirement: レシピの編集

システムは、既存レシピに対して S04 レシピ編集画面を開き、名前 / 人数 / タグ / 材料 / 手順 / メモを再編集して保存できることを SHALL 保証する。
編集画面は開いた時点で既存値がロードされ、保存で内容が置き換わる。編集モードと新規モードは同じ画面レイアウトで、ヘッダタイトルと保存時の挙動
(新規追加 / 上書き) のみが異なる。

#### Scenario: 既存レシピの人数を変更して保存する

- **GIVEN** レシピ「肉じゃが」(人数 2) が登録されている
- **AND** ユーザーが S04 編集画面をそのレシピで開いている
- **WHEN** 画面上に既存の名前・人数・材料・手順・メモが初期値としてロードされている
- **AND** ユーザーが人数を「3」に変更して「保存」を押す
- **THEN** 保存後、画面は S02 レシピ一覧に戻る
- **AND** 「肉じゃが」の更新日 (updatedAt) が保存時点に更新されている
- **AND** アプリ再起動後も人数「3」が保持されている

#### Scenario: 材料を追加してから保存する

- **GIVEN** レシピ「肉じゃが」の S04 編集画面が開いている
- **WHEN** ユーザーが「材料を追加」を押し、追加行に名前 / 量 / 単位を入力する
- **AND** 「保存」を押す
- **THEN** 保存後、そのレシピの材料に追加分が含まれている

### Requirement: 未保存変更のキャンセル確認

システムは、S04 レシピ登録/編集画面で入力内容が初期値から変更されている (dirty である) 状態で「キャンセル」が押された場合、
変更を破棄するかを問う確認ダイアログを SHALL 表示する。dirty でない場合は確認なしで呼び出し元に戻る。

#### Scenario: dirty 状態でキャンセルを押すと確認される

- **GIVEN** ユーザーが S04 新規登録画面で名前欄に文字を入力した状態
- **WHEN** ユーザーが「キャンセル」を押す
- **THEN** 「未保存の変更を破棄しますか」旨の確認ダイアログが表示される
- **WHEN** ユーザーが「破棄」を選ぶ
- **THEN** 画面は呼び出し元 (S02) に戻り、入力内容は保存されていない

#### Scenario: dirty でない状態のキャンセルは確認をスキップする

- **GIVEN** ユーザーが S04 新規登録画面を開き、まだ何も入力していない
- **WHEN** ユーザーが「キャンセル」を押す
- **THEN** 確認ダイアログは表示されず、画面は呼び出し元 (S02) に戻る

#### Scenario: 確認ダイアログで「編集を続ける」を選ぶと画面に留まる

- **GIVEN** dirty 状態で「キャンセル」を押し、確認ダイアログが表示されている
- **WHEN** ユーザーが「編集を続ける」を選ぶ
- **THEN** ダイアログが閉じ、S04 の入力内容はそのまま保持される

### Requirement: 保存後の一覧遷移とハイライト

システムは、S04 で保存が成功した際、S02 レシピ一覧に戻り、保存対象のレシピ行を他の行と視覚的に区別できる形で SHALL 強調表示する。
強調表示は少なくともユーザーが一覧に戻った直後の視認を助ける水準で提供され、後続の別行選択や検索操作で自然に解除される。

#### Scenario: 新規保存後、追加された行がハイライトされる

- **GIVEN** ユーザーが S04 新規登録画面で「肉じゃが」を保存した
- **WHEN** 画面が S02 レシピ一覧に戻る
- **THEN** 「肉じゃが」の行が他の行と区別できるハイライトで表示される

#### Scenario: 編集保存後、対象の行がハイライトされる

- **GIVEN** ユーザーが S04 編集画面で既存レシピ「肉じゃが」の人数を更新して保存した
- **WHEN** 画面が S02 レシピ一覧に戻る
- **THEN** 「肉じゃが」の行が他の行と区別できるハイライトで表示される

### Requirement: 手順とメモの Markdown 記法対応

システムは、S04 レシピ登録/編集画面の手順欄とメモ欄で、Markdown 記法のテキストをそのまま受け付けて保存することを SHALL 保証する。
書き手側 (S04) ではプレーンテキスト入力として振る舞い、Markdown レンダリングは行わない。読み手側の描画 (見出し / リスト / 強調等) は
S03 レシピ詳細ドロワーで追加される予定。手順欄には Markdown 記法が使える旨のヒントを表示する。

#### Scenario: Markdown 記法のテキストが素通しで保存・再表示される

- **GIVEN** ユーザーが S04 編集画面で手順欄に `## 下ごしらえ\n- 玉ねぎを切る\n- 豚肉を漬ける` を入力し、「保存」を押した
- **WHEN** 同じレシピを再度 S04 編集画面で開く
- **THEN** 手順欄に入力した Markdown テキストが変換されず、そのままの文字列で表示される

#### Scenario: 手順欄には Markdown が使える旨のヒントが表示される

- **WHEN** ユーザーが S04 新規登録画面を開く
- **THEN** 手順欄の近くに「Markdown 記法で書けます」旨のヒントが表示されている

### Requirement: 入力バリデーション

システムは、S04 レシピ登録/編集画面での保存時に、次の入力制約を SHALL 検証する。制約に違反する入力は保存されず、対応するフィールド近傍に
エラー表示を出す。

- レシピ名は 1 文字以上 200 字以内 (trim 後)。
- 人数は 1 以上 99 以下の整数。
- 材料行を追加した場合、その行の名前は必須 (trim 後で 1 文字以上)。量と単位は空を許容する。
- 手順テキストは 4000 字以内。
- メモテキストは 2000 字以内。
- タグ 1 個は trim 後 30 字以内。空タグは黙って捨てる。

#### Scenario: レシピ名が 200 字を超えると保存できない

- **GIVEN** ユーザーが S04 新規登録画面を開いている
- **WHEN** ユーザーが名前欄に 201 字以上の文字列を入力して「保存」を押す
- **THEN** 保存は行われず、名前欄近傍に「文字数の上限を超えています」旨のエラー表示が出る
- **AND** 画面は S04 のままである

#### Scenario: 人数が 0 や 100 だと保存できない

- **GIVEN** ユーザーが S04 新規登録画面で名前に「x」を入力している
- **WHEN** 人数欄に「0」または「100」を入力して「保存」を押す
- **THEN** 保存は行われず、人数欄近傍にエラー表示が出る

#### Scenario: 材料行に名前を入れずに保存すると弾かれる

- **GIVEN** ユーザーが S04 新規登録画面で名前に「x」を入力している
- **AND** 材料行を 1 行追加し、量と単位だけを入力して名前欄を空にしている
- **WHEN** ユーザーが「保存」を押す
- **THEN** 保存は行われず、その材料行の名前欄近傍にエラー表示が出る
- **AND** 材料行を追加していない (0 件のまま) の場合、この検証は発火せず保存できる

#### Scenario: 手順テキストが 4000 字を超えると保存できない

- **GIVEN** ユーザーが S04 新規登録画面で名前に「x」を入力している
- **WHEN** 手順欄に 4001 字以上の文字列を入力して「保存」を押す
- **THEN** 保存は行われず、手順欄近傍にエラー表示が出る
- **AND** 手順欄の下に残り字数の表示が出ている (負数になっている)
