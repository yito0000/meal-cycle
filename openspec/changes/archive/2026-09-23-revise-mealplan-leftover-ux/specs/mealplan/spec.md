## ADDED Requirements

### Requirement: 作り置きを広げる (統合ダイアログ)

システムは、1 品の作り置きを複数の (対象日, 対象時間帯) にまとめて広げる操作を SHALL 提供する。
ユーザーは品行 `⋯ → 作り置きを広げる` から統合ダイアログを開き、以下を 1 回の操作で反映できる:

1. **対象セル選択**: 対象日 (起点日から未来 max(`LeftoverCopyPresets`) − 1 日ぶん、実装時点は起点日 +
   3 日 = 4 行) × 対象時間帯 (朝食 / 昼食 / 夕食) の格子から、複数セルをチェックボックスで選べる。起点
   セル自身は選択不可。作り置きは翌日以降に伸ばす操作なので過去方向の対象日は載せない。行数の上限は
   `CopyLeftover` の `days` が `LeftoverCopyPresets` の要素値しか受け付けないための帰結
   (許容最大は起点 + max − 1 日)。この上限を超える広範囲コピーは別 proposal で backend 側 presets の
   拡張が入るまで扱わない
2. **既定選択**: 起点日以降の同じ時間帯を min(`LeftoverCopyPresets`) (実装時点は 2 日) だけチェック済み
   で開く。旧「連続 N 日 = 2 日」相当の 1 クリック操作を維持する
3. **作り置き / 別調理の選択**: ダイアログ内セグメントで選ぶ。既定は「作り置き」
4. **衝突解決の選択**: チェック済みセルのうち既存割当があるセルは背景色で示唆する。ダイアログ内
   セグメント `追加 / 上書き` で衝突挙動を選ぶ。既定は「追加」
5. **反映**: OK 押下でチェック済みセル群を反映する。同時間帯のセル群は `CopyLeftover` 相当、
   別時間帯のセル群は `CopyToOtherMeal` 相当で並行反映される

現在表示されている対象日レンジ外 / 起点セル自身 / 既に同じ作り置きに属するセルは選択候補に出さない。
ダイアログをキャンセルで閉じた場合は割当は変わらない。

#### Scenario: 起点日 + 2 日ぶん同時間帯が既定でチェックされる

- **WHEN** 月曜・夕食の「肉じゃが」の行の `⋯ → 作り置きを広げる` を開く
- **THEN** 格子の「火曜・夕食」「水曜・夕食」が既定でチェック済みで表示される
- **AND** 起点セル「月曜・夕食」は選択不可 (グレーアウト表示)

#### Scenario: 対象日 × 時間帯を自由に組み合わせて広げる

- **WHEN** 月曜・夕食の「肉じゃが」を、格子で「火曜・夕食」「水曜・昼食」「木曜・夕食」を
  チェックして OK を押す
- **THEN** 3 セルすべてに「肉じゃが」の行が追加される
- **AND** 3 行は起点行と同じ作り置きに属し、UI で共通の枠色と 🔗 アイコンが表示される

#### Scenario: 別調理を選ぶと各セルが独立した作り置きになる

- **WHEN** 統合ダイアログで「火曜・夕食」「水曜・夕食」をチェックし、モードを「別調理」で OK を押す
- **THEN** 各コピー先セルは起点とは異なる独立した作り置きに属し、UI で共通枠色は表示されない

#### Scenario: 衝突セルは追加 / 上書きの指定に従って反映される

- **WHEN** 「火曜・昼食」に「みそ汁」が既にある状態で、統合ダイアログで「火曜・昼食」をチェックし、
  衝突挙動を「追加」で OK を押す
- **THEN** 「火曜・昼食」は「みそ汁」「肉じゃが」の 2 品構成になる
- **AND** 起点行と火曜・昼食の「肉じゃが」は同じ作り置きに属する

#### Scenario: 起点日 + 未来 3 日ぶんの 4 行だけが表示される

- **WHEN** 月曜・夕食を起点に統合ダイアログを開く
- **THEN** 格子には月曜〜木曜の 4 行だけが表示される (過去日と金曜以降は行として存在しない)
- **AND** ダイアログ内に対象日を追加する「もっと表示」系のボタンは無い (backend 側 presets の
  拡張が入る別 proposal で導入予定)

#### Scenario: キャンセルすると割当は変わらない

- **WHEN** 統合ダイアログで複数セルをチェックした後、キャンセルで閉じる
- **THEN** meal_plans は変化せず、UI 上も何も追加されない

## MODIFIED Requirements

### Requirement: 事後編集による作り置きの外し / まとめ

システムは、割当済みの行の作り置き帰属を後から変更できる UI を SHALL 提供する。ユーザーは品行 `⋯`
メニューから「作り置きから外す」操作 (作り置きを解体する) と、「他の作り置きにまとめる」操作
(別々に割り当てた同一レシピを 1 つの作り置きに寄せる) を実行できる。

「作り置きから外す」は、対象行が属する作り置き全体を対象に、起点日 (バッチ内で最も古い日付の行) だけを
残し、それ以外の同じ作り置きの行を全削除する。残った起点行は新しい単独作り置きになる。既に単独作り置き
だった行に対してこの操作を選んだときは何も起きない。

「他の作り置きにまとめる」は、以下の 2 条件を **すべて** 満たす候補にのみまとめられる (「1 回の調理
でできる作り置き」の意味を守るため):

1. **同じレシピ** である
2. 対象行から **±max(`LeftoverCopyPresets`) 日以内** (実装時点は ±4 日) の日付範囲に含まれる

「同時間帯」制約は無い — 別時間帯の作り置きにも合流できる。「1 日飛ばし」など、連続でない日付は
上記 2 条件を満たす限り許容する。

各メニュー項目の表示は行の作り置き状態に応じて出し分けられる:

- **「作り置きから外す」**: その行が **複数行の作り置きに属している** ときだけ表示
- **「作り置きを広げる」**: どの状態の行でも表示 (単独作り置きなら「1 バッチ = その行」として
  広げ側に、複数行作り置きなら既存バッチに新行を追加)

旧メニュー項目「この品を連続 N 日」および「別の時間帯にも作り置きを追加」は「作り置きを広げる」に
統合されるため、表示しない。

#### Scenario: 作り置きから外すと起点日だけが残る

- **WHEN** 月・火・水曜・夕に同じ作り置きの「肉じゃが」が並んでいる状態で、火曜の行の
  `⋯ → 作り置きから外す` を選ぶ
- **THEN** 火曜と水曜の「肉じゃが」の行が削除される
- **AND** 月曜の「肉じゃが」だけが残り、その行は新しい単独作り置きに属する

#### Scenario: 単独作り置きの行に対して外す操作は何もしない

- **WHEN** ある行が単独の作り置き (1 行のみ) に属している状態で、その行の
  `⋯ → 作り置きから外す` を選ぶ
- **THEN** その行はそのまま残り、`meal_plans` は変化しない

#### Scenario: 同一レシピの近い日付の作り置きにまとめる

- **WHEN** 「火曜・夕」に単独で割り当てた「肉じゃが」があり、「月曜・夕」に別の作り置きの「肉じゃが」が
  ある状態で、「火曜・夕」の `⋯ → 他の作り置きにまとめる` から「月曜・夕」の作り置きを選ぶ
- **THEN** 火曜の「肉じゃが」が月曜の作り置きに移り、両行が同じ作り置きに属する

#### Scenario: 別時間帯の同一レシピ作り置きにもまとめられる

- **WHEN** 「火曜・昼食」に単独で割り当てた「肉じゃが」があり、「月曜・夕食」に別の作り置きの
  「肉じゃが」がある状態で、「火曜・昼食」の `⋯ → 他の作り置きにまとめる` から「月曜・夕食」の作り置きを
  選ぶ
- **THEN** 火曜の「肉じゃが」が月曜の作り置きに移り、時間帯が異なっても両行が同じ作り置きに属する

#### Scenario: まとめ候補は同じ 時間帯・同じレシピ・±4 日以内だけを提示する

- **WHEN** ユーザーが `⋯ → 他の作り置きにまとめる` を開く
- **THEN** 候補は「同じレシピ」「対象行から ±4 日以内」の 2 条件を全て満たす他の作り置きが表示される
  (「同時間帯」制約は廃止 — 別時間帯の作り置きも候補に含む。別レシピ / 日付レンジ外は除外)

#### Scenario: レシピが違う作り置きにはまとめられない

- **WHEN** 「火曜・夕」の「肉じゃが」に対して、周辺日 (±4 日) に「みそ汁」の作り置きしかない状態で
  `⋯ → 他の作り置きにまとめる` を開く
- **THEN** 「みそ汁」の作り置きは候補に表示されない

#### Scenario: 日付レンジ外の作り置きにはまとめられない

- **WHEN** 「金曜・夕」の「肉じゃが」に対して、5 日以上前の同レシピ作り置きしかない状態で
  `⋯ → 他の作り置きにまとめる` を開く
- **THEN** 5 日以上前の作り置きは候補に表示されない

#### Scenario: 1 日飛ばした同一レシピの行はまとめられる

- **WHEN** 月・火に同じ作り置きの「肉じゃが」があり、金にも単独で「肉じゃが」があり (水木は別献立)、
  金の行の `⋯ → 他の作り置きにまとめる` から月火の作り置きを選ぶ
- **THEN** 金の「肉じゃが」が月火の作り置きに移り、月・火・金の 3 行が同じ作り置きに属する

#### Scenario: 単独作り置きの行には「作り置きから外す」項目が出ない

- **WHEN** ある行が単独の作り置き (1 行のみ) に属している状態で、その行の `⋯` メニューを開く
- **THEN** メニューに「作り置きから外す」項目は表示されない

#### Scenario: 作り置きに属する行には「この品を連続 N 日」項目が出ない

- **WHEN** どの作り置き状態の行でも `⋯` メニューを開く
- **THEN** 旧メニュー項目「この品を連続 N 日」は表示されない (「作り置きを広げる」に統合済み)
- **AND** 旧メニュー項目「別の時間帯にも作り置きを追加」も表示されない (同じく統合済み)
- **AND** 代わりに「作り置きを広げる」が表示される

## REMOVED Requirements

### Requirement: 作り置きコピー (1 品単位)

**Reason**: 「連続 N 日」フローを「作り置きを広げる」統合ダイアログに吸収したため、単独 Requirement
として保持する必要が無くなった。挙動はすべて新 Requirement「作り置きを広げる (統合ダイアログ)」に
含まれる。

**Migration**: `⋯ → この品を連続 N 日 → 3 日` の操作は `⋯ → 作り置きを広げる` に置き換わる。既定
チェック (起点日 +2 日ぶん同時間帯) がされた状態で開くので、そのまま OK を押せば旧「連続 2 日」相当。
連続 3 日以上を選びたい場合は追加でチェックする。

### Requirement: 連続 N 日コピーの作り置き / 別調理選択

**Reason**: 1 品単位フローが「作り置きを広げる」統合ダイアログに移り、モード選択も統合ダイアログの
セグメントとして吸収された。時間帯全体コピー ( `⋯ → 時間帯全体を連続 N 日コピー` ) は現行のまま
残り、そちらの Requirement「作り置きコピー (時間帯全体)」内にモード選択が inline で記述されている
ため、独立した Requirement は不要。

**Migration**: 旧「連続 N 日 → 作り置き / 別調理」の 2 段ダイアログは、統合ダイアログ 1 画面に
まとまる。時間帯全体コピーの UX は据え置きで、モード選択は「作り置きコピー (時間帯全体)」で
継続する。

### Requirement: 作り置きを別時間帯にも追加

**Reason**: 「別の時間帯にも作り置きを追加」は「作り置きを広げる」統合ダイアログの「対象時間帯を
別の時間帯にチェックする」ケースとして吸収される。単独メニュー / 単独ダイアログとして保持する
必要が無くなった。

**Migration**: `⋯ → 別の時間帯にも作り置みを追加` の操作は `⋯ → 作り置きを広げる` に置き換わる。
統合ダイアログの格子で対象時間帯を選ぶだけで済む。
