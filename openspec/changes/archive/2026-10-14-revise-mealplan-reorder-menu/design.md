## Context

動機は [proposal.md](proposal.md) の Why を、受け入れ条件は [specs/mealplan/spec.md](specs/mealplan/spec.md) を参照。

現状は次のとおりである。

- 時間帯全体の `⋯` メニュー (`MealMenu`) の「並び替え」は、`WeekCalendar` の `handleMealAction` で `pages.meal_plan.errors.unknown` を出すだけで終わる
- 同じセルの中でのドラッグ&ドロップは、`reorderWithinCell(date, meal, sourcePosition, targetPosition)` で並びを組み直し、
  既存の `MealPlanService.ReorderMeal(date, meal, orderedRecipeIDs)` に渡す。
  `reorderWithinCell` は source を target の **前** に差し込む
- 作り置きに属する品 (`batchMemberCount > 1`) は `draggable=false` で、セルの中でも並びを変えられない
- `ReorderMeal` は position だけを振り直し、`batch_id` と `recipe_id` は行ごとそのまま残す
- `locales` の `pages.meal_plan.reorder` (上へ / 下へ / 完了) は、どのコンポーネントからも参照されていない

## Goals / Non-Goals

**Goals:**

- 押しても動かないメニュー項目を無くす
- 作り置きの品を含め、どの品もセルの中で並びを変えられるようにする
- Go 側とバインディングに手を入れない

**Non-Goals:**

- ドラッグ&ドロップの挙動の変更 (作り置きの品をドラッグ可能にすることを含む)

## Decisions

### D1. 「並び替え」の項目をどうするか

**選択肢:**

- (a) 時間帯のメニューから外すだけにする
  — Pros: 変更が最小
  / Cons: 作り置きの品はドラッグできないので、セルの中での並びを変える手段が無くなる
- (b) 時間帯のメニューの「並び替え」から、上下ボタンの並んだ並び替えモードを開く
  — Pros: 当初の spec の想定 (「上下ボタン等の代替 UI」) に沿う
  / Cons: セル内の表示にモードが増え、「他 N 件」に畳まれた品の見せ方も決める必要がある。1 品を動かすのに 3 手 (メニュー、上へ、完了) かかる
- (c) 時間帯のメニューからは外し、品のメニューに「上へ移動」「下へ移動」を足す ← 採用
  — Pros: 1 品を動かすのが 2 手で済む。作り置きの品も動かせる。既存の品メニューの形を崩さない
  / Cons: 品メニューの項目が 2 つ増える

**採用: (c)**。
並び替えの主な手段はドラッグ&ドロップで、メニューはドラッグできない品のための補助である。
補助のためにモードを増やす (b) は割に合わない。

### D2. 項目の出し方

セルに 2 品以上あるときだけ「上へ移動」「下へ移動」を出す。
1 品のセルで押せない項目が 2 つ並ぶと、メニューが無駄に長くなるためである。

先頭と末尾の品では、該当する項目を消さずに `disabled` にする。
品によって項目の数が変わると、メニューを開くたびに項目の位置がずれて押し間違えやすくなるからである。

項目は「この品のレシピ詳細を見る」の下、区切り線の前に置く。
品そのものへの操作 (入れ替え、削除、詳細、移動) と、作り置きへの操作 (広げる、外す、まとめる) を区切り線で分けたままにする。

`CellItemMenu` に `canMoveUp` / `canMoveDown` / `showMove` の 3 つを渡すのではなく、
`position` と `cellItemCount` を渡してメニューの中で決める。
`MealPlanCell` は描画中の `entries` を持っているので、`cellItemCount` はその長さを渡せばよい。
「他 N 件」に畳まれた品があっても、セルの品数は畳む前の数を使う。
末尾に表示された品は「下へ移動」で畳まれた品と入れ替わることになるが、これは spec の「1 つ下の品と入れ替える」どおりの挙動である。

### D3. 並びの組み直し

既存の `reorderWithinCell` を使い、新しい関数は作らない。

- 「上へ移動」：`reorderWithinCell(date, meal, position, position - 1)`。source を 1 つ上の品の前に差し込む
- 「下へ移動」：`reorderWithinCell(date, meal, position + 1, position)`。1 つ下の品を source の前に差し込む

`reorderWithinCell` は source を target の前に差し込むので、`(position, position + 1)` を渡しても並びは変わらない。
「下へ移動」は、1 つ下の品を上に動かす形に置き換えて同じ関数に流す。
このことを `week-calendar.tsx` の呼び出し箇所に WHY のコメントで残す。

### D4. 「セル内の品表示」の要件でメニュー項目を列挙しない

現行の「セル内の品表示」は、品のメニューを「入れ替え / 削除 / 詳細 / 連続 N 日」と列挙している。
これはすでに実装とずれており (「連続 N 日」は「作り置きを広げる」に置き換わった)、メニューに項目を足す proposal のたびに書き換えが要る。
並行して `add-mealplan-cooked-mark` も品メニューに項目を足すので、同じ要件を 2 つの change が MODIFIED すると archive で衝突する。

そこで、この change で列挙を外し、「各メニューの項目は、その操作を定める要件に従う」とだけ書く。
メニューに出る項目は、「1 品の入替 / 削除 / 詳細表示」「時間帯内の並び替え」「作り置きを広げる (統合ダイアログ)」などの各要件が定める。
時間帯全体のメニューに「並び替え」が無いことは、「セル内の品表示」に Scenario を 1 つ足して固定する。

## Risks / Trade-offs

- [Risk] 同じセルに同じレシピが 2 品あると、`ReorderMeal` はレシピ ID で行を探すため、並べ替え後にどちらの行がどの位置に来るかが入れ替わりうる。
  作り置きの枠色は行の `batch_id` に付くので、見た目の並びが意図と食い違う可能性がある
  → 既存のドラッグ&ドロップでも同じ条件を持っており、この change で悪化はしない。同じセルに同じレシピを 2 品置く使い方は想定していない
- [Risk] 「他 N 件」に畳まれたセルで末尾の品を「下へ移動」すると、その品が畳まれて見えなくなる
  → spec どおりの挙動として受け入れる。畳まれた品は期間を 1 週に戻せば見える

## Migration Plan
