## ADDED Requirements

### Requirement: 入力バリデーション

システムは、割当系メソッドが受け取る入力を検証し、不正値ではデータを変更せずに型付きエラーを SHALL 返す。UI 側はこの
エラーコードを人間可読メッセージに変換して表示する。call site でのリテラル閾値は禁止で、許容値の下敷き (作り置きコピー
可能日数) は `config.LeftoverCopyPresets` から引く。

#### Scenario: 不正な日付形式は拒否される

- **WHEN** ユーザーまたは呼び出し元が "2026/01/30" や "20260130" のような "YYYY-MM-DD" 以外の date を渡す
- **THEN** システムは `ErrInvalidDate` を返し、`meal_plans` は変化しない

#### Scenario: 不明な slot 値は拒否される

- **WHEN** 呼び出し元が `breakfast` / `lunch` / `dinner` 以外の slot を渡す
- **THEN** システムは `ErrInvalidSlot` を返し、`meal_plans` は変化しない

#### Scenario: 存在しない position を指定する入替 / 削除は拒否される

- **WHEN** ReplaceEntry または RemoveEntry が対象 (日付, slot) に存在しない position を指定する
- **THEN** システムは `ErrEntryNotFound` を返し、`meal_plans` は変化しない

#### Scenario: 負の position は拒否される

- **WHEN** ReplaceEntry または RemoveEntry が負の position を渡す
- **THEN** システムは `ErrInvalidPosition` を返し、`meal_plans` は変化しない

#### Scenario: 並び替えの入力集合が既存 slot と不一致

- **WHEN** ReorderSlot に渡された recipe ID 集合が既存 slot の recipe ID 集合と要素として一致しない (欠け / 追加 /
  重複がある)
- **THEN** システムは `ErrReorderMismatch` を返し、`meal_plans` は変化しない

#### Scenario: 作り置きコピーの日数はプリセット外を拒否する

- **WHEN** CopyLeftover が `config.LeftoverCopyPresets` に含まれない days (例: 5、1、0、-1) を渡す
- **THEN** システムは `ErrInvalidCopyDays` を返し、`meal_plans` は変化しない

### Requirement: 割当データの永続化

システムは、(日付, slot, position, レシピ) の割当を再起動しても保持 SHALL する。同一 (日付, slot) 内では position は
0 起点の連番 (欠番なし) であり、レシピは登録済みレシピの参照でなければならない。

#### Scenario: 割当したエントリが再起動後も残る

- **WHEN** ユーザーがある (日付, slot) にレシピを割り当てて S01 を閉じる
- **AND** アプリを再起動して同じ週を表示する
- **THEN** 割り当てた品が同じ日付・slot・position で復元される

#### Scenario: 削除された品の後ろは position が詰まる

- **WHEN** ある (日付, slot) に position=0..2 の 3 品がある状態で position=1 の品を削除する
- **THEN** 残った 2 品は position=0, 1 に採番し直される

#### Scenario: 存在しないレシピは割当できない

- **WHEN** ユーザーが削除済みレシピの ID で割当を要求する
- **THEN** システムはエラーコードを返し、`meal_plans` は変化しない

### Requirement: 空セルへの 1 品目割当

システムは、空セル (0 品) に対して 1 品目を追加する UI を SHALL 提供する。追加は「レシピを 1 件選ぶ → dialog が閉じる →
セルにその 1 品だけが表示される」で完了しなければならない。

#### Scenario: 空セルの `＋` からレシピを選んで割当する

- **WHEN** ユーザーが空セルの `＋` をクリックする
- **THEN** レシピ選択ダイアログが開く
- **AND** ユーザーがレシピを 1 件選ぶと dialog が閉じ、そのセルに 1 品だけが position=0 で表示される

#### Scenario: 選択せずに閉じると割当は発生しない

- **WHEN** ユーザーがダイアログを開いてから閉じるボタンや背景クリックで閉じる
- **THEN** 対象セルは空セルのままで、`meal_plans` は変化しない

### Requirement: 割当済セルへの品追加

システムは、既に 1..N 品が割り当てられた slot に対して、末尾に品を追加する UI を SHALL 提供する。追加された品の
position は既存の最大 position + 1 であり、既存品の position は変わらない。

#### Scenario: 1 品ある slot にもう 1 品追加すると 2 品目が下に並ぶ

- **WHEN** ある (日付, slot) に「肉じゃが」(position=0) が 1 品あり、ユーザーがセル右上の `＋` を押して「みそ汁」を選ぶ
- **THEN** そのセルは「肉じゃが」(position=0)、「みそ汁」(position=1) の 2 行になる

#### Scenario: セル右上 `＋` は 0 品セルでは出さない

- **WHEN** ある (日付, slot) が空セルである
- **THEN** セル右上の `＋` は表示されず、空セル中央の `＋` だけが表示される (両方は出さない)

### Requirement: 1 品の入替 / 削除 / 詳細表示

システムは、割当済みの各品行に対し `⋯` メニューを SHALL 提供する。メニューは「入れ替え」「この品を削除」「この品のレシピ
詳細を見る」「この品を連続 N 日」を含む。入替は 1 品だけを別レシピに置き換え、削除は 1 品だけを消す。詳細表示は S03
レシピ詳細ドロワーを開き、閉じたら呼び出し元の S01 に戻す。

#### Scenario: 1 品だけ入れ替える

- **WHEN** ある (日付, slot) に「肉じゃが」「みそ汁」が並んでおり、ユーザーが「みそ汁」の `⋯ → 入れ替え → 豚汁` を選ぶ
- **THEN** そのセルは「肉じゃが」「豚汁」の 2 品になる (position は変わらない)

#### Scenario: 1 品だけ削除する

- **WHEN** ある (日付, slot) に「肉じゃが」「みそ汁」が並んでおり、ユーザーが「みそ汁」の `⋯ → この品を削除` を選ぶ
- **THEN** そのセルは「肉じゃが」1 品だけになる (position=0)

#### Scenario: 詳細を開くと S02 を経由せずに S01 に戻れる

- **WHEN** ユーザーが品行 `⋯ → この品のレシピ詳細を見る` を選ぶ
- **THEN** S03 レシピ詳細ドロワーが開き、閉じると S02 を経由せずに呼び出し元の S01 に戻る

### Requirement: slot 全体のクリア

システムは、slot 全体を一括削除する UI を SHALL 提供する。実行後、その (日付, slot) は空セルに戻る。

#### Scenario: slot 右下 `⋯ → slot 全体をクリア` で全削除

- **WHEN** ある (日付, slot) に 2 品ある状態でユーザーが slot 右下 `⋯ → slot 全体をクリア` を選ぶ
- **THEN** その (日付, slot) の全品が削除され、空セルになる

### Requirement: slot 内の並び替え

システムは、slot 内の品の並び順 (position) を、ユーザーが変更できる UI を SHALL 提供する。並び替え結果は保存され、再表示
時にも維持される。ドラッグ&ドロップは要件ではなく、上下ボタン等の代替 UI で満たしてよい。

#### Scenario: 2 品目を上に動かすと 1 品目と入れ替わる

- **WHEN** ある (日付, slot) に「肉じゃが」(position=0)、「みそ汁」(position=1) がある状態でユーザーが「みそ汁」の
  並び替え UI で「上へ」を選ぶ
- **THEN** そのセルは「みそ汁」(position=0)、「肉じゃが」(position=1) の順に並び替えられる

#### Scenario: 並び替えは再起動後も維持される

- **WHEN** 並び替えを保存してからアプリを再起動し、同じ週を表示する
- **THEN** 並び順は並び替え後のまま復元される

### Requirement: レシピ選択ダイアログ

システムは、割当や入替のためのレシピ選択 UI を「S02 のミニ版」としてダイアログで SHALL 提供する。ダイアログはレシピ名の
部分一致検索を持ち、選択で dialog が閉じる。S02 本画面には遷移しない。

#### Scenario: 検索でレシピを絞り込める

- **WHEN** レシピ選択ダイアログでユーザーが検索欄に「肉」と入力する
- **THEN** 一覧が「肉」を名前に含むレシピのみに絞り込まれる

#### Scenario: 選択で dialog が閉じ、割当が反映される

- **WHEN** ユーザーが検索結果から「肉じゃが」を選ぶ
- **THEN** ダイアログが閉じ、呼び出し元セルに「肉じゃが」の割当が反映される

#### Scenario: 本画面 S02 には遷移しない

- **WHEN** ユーザーがレシピを選択またはキャンセルする
- **THEN** 画面は S01 のままで、レシピ一覧画面 (S02) には遷移しない

### Requirement: 作り置きコピー (1 品単位)

システムは、1 品の作り置きコピーを SHALL 提供する。ユーザーは品行 `⋯ → この品を連続 N 日` から日数 (2 / 3 / 4 日)
を選び、コピー元の (日付, slot) を起点に連続する N 日分の同じ slot に、その 1 品を追加する。N には起点日自身を含む。

#### Scenario: 空だった連続日に 1 品が入る

- **WHEN** 「月曜・夕」に「肉じゃが」1 品があり、火〜金・夕が空の状態でユーザーが `⋯ → 連続 3 日` を選ぶ
- **THEN** 「月曜・夕」「火曜・夕」「水曜・夕」の各 slot に「肉じゃが」が入り、木曜・夕と金曜・夕は空のままになる

#### Scenario: 起点自身の日にも重複追加しない

- **WHEN** 「月曜・夕」に「肉じゃが」1 品がある状態で `⋯ → 連続 3 日` を選ぶ
- **THEN** 「月曜・夕」の「肉じゃが」は 1 品のままで、同じレシピが 2 回並ぶことはない

### Requirement: 作り置きコピー (slot 全体)

システムは、slot 全体 (複数品) の作り置きコピーを SHALL 提供する。ユーザーは slot 右下 `⋯ → slot 全体を連続 N 日
コピー` から日数を選び、コピー元 slot の全品 (position 順) を連続 N 日分の同じ slot に反映する。

#### Scenario: 2 品構成を 3 日分コピーする

- **WHEN** 「月曜・夕」に「肉じゃが」「みそ汁」があり、火〜金・夕が空の状態でユーザーが slot 右下
  `⋯ → slot 全体を連続 3 日` を選ぶ
- **THEN** 「月曜・夕」「火曜・夕」「水曜・夕」の各 slot に「肉じゃが」「みそ汁」の 2 品が position 順で入る

### Requirement: 作り置きコピー先の衝突解決

システムは、作り置きコピー先の (日付, slot) に既存の割当があるとき、ユーザーに「追加」「上書き」「キャンセル」の
選択を SHALL 求める。「追加」はコピー元品を既存品の末尾に append し、「上書き」は既存 slot を空にしてからコピー元品で
置き換え、「キャンセル」は割当を一切変更しない。

#### Scenario: 追加を選ぶと元の品と併存する

- **WHEN** 「火曜・夕」に「豚汁」がある状態で「月曜・夕」の「肉じゃが」を連続 3 日でコピーし、「追加」を選ぶ
- **THEN** 「火曜・夕」は「豚汁」「肉じゃが」の 2 品構成になる

#### Scenario: 上書きを選ぶと既存 slot が置き換わる

- **WHEN** 同じ状況で「上書き」を選ぶ
- **THEN** 「火曜・夕」の既存 slot が全削除され、「肉じゃが」1 品だけになる

#### Scenario: キャンセルを選ぶと何も変わらない

- **WHEN** 同じ状況で「キャンセル」を選ぶ
- **THEN** 「月曜・夕」を含む全ての (日付, slot) は元の状態のまま維持される

#### Scenario: 衝突がない場合はダイアログを出さない

- **WHEN** コピー先の (日付, slot) がすべて空である
- **THEN** 衝突解決ダイアログは表示されず、そのままコピーが実行される

## MODIFIED Requirements

### Requirement: セル内の品表示

システムは、各 (日付, slot) セル内に、その slot に割り当てられた品を **position 昇順** で縦積み表示 SHALL する。
0 品の slot は空セルとして表示し、1..N 品はレシピ名を 1 行 1 品で描画する。各品行にはその品に対する `⋯` メニュー
(入れ替え / 削除 / 詳細 / 連続 N 日) を、slot 右下には slot 全体の `⋯` メニュー (全クリア / 全体連続 N 日 / 並び替え)
を配置する。

#### Scenario: 0 品の slot は空セルになる

- **WHEN** ある (日付, slot) に紐づく品が 1 つも無い
- **THEN** そのセルは空セルとして表示される (レシピ名の描画は無い)
- **AND** 空セル中央の `＋` ボタンが表示される

#### Scenario: 複数品は position 順に縦積みされる

- **WHEN** ある (日付, slot) に position=0 の「肉じゃが」と position=1 の「みそ汁」が紐づいている
- **THEN** そのセル内に「肉じゃが」「みそ汁」の順で 2 行が縦に並んで表示される
- **AND** 各行の右端に品単位の `⋯` メニューが表示される

#### Scenario: 品数超過は省略表示になる

- **WHEN** ある (日付, slot) に 4 品が紐づいている
- **THEN** そのセルには先頭の一定件数 (2 品) が表示される
- **AND** その後ろに「他 N 件」の省略行が 1 行表示される

#### Scenario: 割当済セルには右上に `＋`、右下に slot `⋯` が並ぶ

- **WHEN** ある (日付, slot) に 1 品以上が紐づいている
- **THEN** セル右上に品追加用の `＋` が、セル右下に slot 全体用の `⋯` メニューが表示される

### Requirement: 週データ取得の境界

システムは、週の 7 日 × 全 slot 分の献立エントリを 1 回の取得で SHALL 返す。取得結果は「エントリの配列」であり、
(日付, slot, position) の 3 つ組で並び順が一意に決まる。エントリはレシピ ID とレシピ名の両方を含み、レシピ名は
`recipes` テーブルとの join で解決した表示用の値である。

#### Scenario: 7 日分のエントリが 1 回で得られる

- **WHEN** 画面が対象週の献立を要求する
- **THEN** 応答には対象週の月曜〜日曜のいずれかに属するエントリのみが含まれる
- **AND** 各エントリは日付・slot・position・レシピ ID・レシピ名を持つ

#### Scenario: 空の slot はエントリを持たない

- **WHEN** ある (日付, slot) に紐づく品が 0 品である
- **THEN** その (日付, slot) に対応するエントリは応答に含まれない (「空を表す明示エントリ」は返さない)

#### Scenario: レシピ名は取得時点の最新値

- **WHEN** あるレシピの名称が変更されたあとで、そのレシピを含む週を再取得する
- **THEN** 応答内の該当エントリのレシピ名は変更後の値になる
