## Context

動機は proposal.md の Why を参照。

- S05 の在庫は `FridgeService.List` / `Update` / `Delete` / `Restore` で扱っており、行内編集と削除の元に戻すはすでに動いている
- 行内編集は同時に 1 行までで、編集中は他の行の操作を無効にしている (`fridge-table.tsx`)
- 量の検証は Go の `validateStockInput` が正で、フロントの `stock-form.ts` は同じ規則で欄の下にエラーを出す
- 常備品は 3 つの状態ボタンで 1 回の操作で切り替わる (add-fridge-staples)

## Goals / Non-Goals

**Goals:**

- 冷蔵庫の前で、1 行あたり 1〜2 回の操作で在庫の見直しを終えられるようにする
- 既存の更新、削除、元に戻すの経路だけを使い、Go 側を変えない

**Non-Goals:**

- 見直しの結果を保存すること (proposal.md の Non-goals)

## Decisions

### D1. 入口: 見直しの状態を切り替える

**選択肢:**

- (a) 各行に常に「ある / 減った / ない」を出す — Pros: 切替が要らない /
  Cons: 普段の S05 の操作列が 5 つのボタンになり、「ある」は見直しの最中にしか意味を持たない
- (b) 「見直す」で状態を切り替え、その間だけ 3 つのボタンを出す ← 採用 — Pros: 普段の画面を変えない。見直し済みの件数を出せる /
  Cons: 切替の操作が 1 回増える
- (c) 1 行ずつ大きく出すウィザード形式のダイアログ — Pros: 冷蔵庫の前で見やすい /
  Cons: 一覧の文脈 (同じ食材の別の行、期限の並び) が見えなくなる。画面が 1 つ増える

**採用: (b)**。理由: 見直しは週に 1〜2 回の作業で、普段の操作列を増やす理由にならない。一覧のまま進めるほうが同名の行を見比べやすい。

### D2. 「減った」の入力: 量の欄だけを入力欄にする

行内編集 (全項目を入力欄にする) を流用せず、量の欄だけを入力欄に変える。
今の量を選択した状態でフォーカスし、数字を打てば置き換わるようにする。
Enter で `FridgeService.Update` に食材名 / 単位 / 賞味期限を今の値のまま、量だけ変えて送る。Esc で入力欄を閉じ、見直し済みにしない。

**選択肢:**

- (a) 既存の行内編集を開く — Pros: 実装が要らない / Cons: 4 つの欄のうち量にフォーカスを移す操作が増え、保存ボタンまで手が動く
- (b) 量の欄だけを入力欄にする ← 採用 — Pros: 打って Enter の 2 動作で終わる / Cons: 量以外を直したいときは見直しを終えてから編集する

**採用: (b)**。理由: 見直しで変わるのはほぼ量だけである。食材名や期限の間違いは見直しの対象外とする。

### D3. 見直し済みの印はフロントのメモリに持つ

見直し済みの在庫 ID の集合を `fridge.tsx` の state に持ち、「見直しを終える」かサイドバーで画面を離れたときに捨てる。

他案として `stock_items` に `reviewed_at` 列を足すことも検討したが、使う画面が無いまま列だけ増えるので見送る (proposal.md の後続への引き継ぎ)。

### D4. フォーカスの移り方

「ある」「減った」の確定、「ない」の後は、表示中の並び順で次の未見直しの行の「ある」ボタンにフォーカスを移す。
末尾まで見直したら「見直しを終える」にフォーカスを移す。
次の行を求める処理は `stock-review.ts` の純関数 `nextUnreviewedId(rows, reviewed, currentId)` にし、Vitest で確かめる。

「ない」を通知の「元に戻す」で戻した行は、見直し済みの集合から外す (戻った行はまだ確かめていないため)。

### D5. 見直しの状態で使えるもの

- インライン追加行、検索欄、並び替え：使える。見直しの最中に見つけた新しい食材をその場で足せるようにする
- 行内編集の「編集」：出さない。D2 の量の入力欄と同時に開くと、1 行までの制約の扱いが二重になる
- 見直しの件数 M は検索で絞った後の行数ではなく、在庫の全行数にする。検索は特定の食材を探す操作で、見直しの範囲を変える意図ではない

## Risks / Trade-offs

- [Risk] 見直しの最中に別の画面へ移ると、見直し済みの印が消えて最初からになる
  → 印は「どこまで確かめたか」の目安でしかなく、データは都度保存されている。消えても在庫は正しい
- [Risk] 「ない」を連打して誤って消す → 通知の「元に戻す」で戻せる。通知は複数件を積み重ねて表示する (今の削除と同じ)
- [Risk] 量の欄に 0 を入れて「ない」のつもりで Enter を押す → 今の検証どおりエラーを欄の下に出し、「ない」を押すよう案内する文言にする
