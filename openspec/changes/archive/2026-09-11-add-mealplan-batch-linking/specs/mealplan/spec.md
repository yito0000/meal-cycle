## ADDED Requirements

### Requirement: 作り置きの意味付け

システムは、meal_plans の各行が「同じ 1 回分の作り置き」に属することを SHALL 表現する (内部識別子は `batch_id`)。
同じ作り置きに属する行は 1 回の調理を共有することを意味し、後続の買い物リスト計算は作り置き単位で 1 セットの
材料を計上する。単独割当は行ごとに独立した作り置きに属し、連続 N 日コピーは選択に応じて 1 作り置き共有または
N 個の別調理のどちらかになる。

#### Scenario: 単独割当したエントリはそれぞれ独立した作り置きに属する

- **WHEN** ユーザーが同じ (日付, slot) に別々の操作で 2 品を割り当てる
- **THEN** その 2 品は互いに異なる作り置きに属する

#### Scenario: 作り置き情報は再起動しても保持される

- **WHEN** 作り置き共有のある割当を保存してからアプリを再起動する
- **THEN** 作り置きの共有関係は復元される (同じ集合の行が同じ作り置きに属し続ける)

#### Scenario: 作り置きが 1 行しか含まないと視覚識別されない

- **WHEN** ある作り置きに属する行が 1 つしか存在しない
- **THEN** UI ではその作り置きの識別色や 🔗 アイコンは表示されない

### Requirement: 連続 N 日コピーの作り置き / 別調理選択

システムは、連続 N 日コピー実行時に「作り置き (1 回分をまとめる)」か「別調理 (N 回に分けて作る)」かを SHALL
選ばせる。既定は「作り置き」。ユーザーが「作り置き」を選ぶと、コピー元と N 日ぶんのコピー先が同一作り置きに
属する。「別調理」を選ぶと、N 日ぶんのコピー先はそれぞれ独立した作り置きに属する。

#### Scenario: 作り置きを選ぶと全日程が同じ作り置きになる

- **WHEN** ユーザーが月曜・夕の「肉じゃが」を「連続 3 日 → 作り置き」でコピーする
- **THEN** 月・火・水曜・夕の「肉じゃが」3 行が同じ作り置きに属する
- **AND** UI ではこの 3 行に共通の枠色と 🔗 アイコンが表示される

#### Scenario: 別調理を選ぶと各日が独立した作り置きになる

- **WHEN** ユーザーが同じ状況で「連続 3 日 → 別調理」を選ぶ
- **THEN** 3 行はそれぞれ独立した作り置きに属し、UI では共通枠色は表示されない

#### Scenario: 既定は「作り置き」

- **WHEN** 連続 N 日コピーのダイアログを開く
- **THEN** 「作り置き」が既定で選択されている状態で表示される

#### Scenario: 作り置き / 別調理の選択は衝突解決 (追加 / 上書き) と独立に選べる

- **WHEN** コピー先に既存割当があり、ユーザーが「追加 + 別調理」または「上書き + 作り置き」等の組み合わせを選ぶ
- **THEN** 衝突解決 (追加 or 上書き) と作り置き / 別調理はそれぞれ独立に反映される

### Requirement: 事後編集による作り置きの外し / まとめ

システムは、割当済みの行の作り置き帰属を後から変更できる UI を SHALL 提供する。ユーザーは品行 `⋯` メニューから
「作り置きから外す」操作 (連続 N 日コピーの逆演算) と、「他の作り置きにまとめる」操作 (別々に割り当てた同一
レシピを 1 つの作り置きに寄せる) を実行できる。

「作り置きから外す」は、対象行が属する作り置き全体を対象に、起点日 (バッチ内で最も古い日付の行) だけを残し、
それ以外の同じ作り置きの行を全削除する。残った起点行は新しい単独作り置きになる。既に単独作り置きだった行に
対してこの操作を選んだときは何も起きない。

「他の作り置きにまとめる」は、以下の 3 条件を **すべて** 満たす候補にのみまとめられる。1 つでも満たさない
場合はその候補は提示されず、外部から指定された場合も操作は拒否される (「1 回の調理でできる作り置き」の
意味を守るため):

1. **同じ slot** に属する
2. **同じレシピ** である
3. 対象行から **±max(`LeftoverCopyPresets`) 日以内** (実装時点は ±4 日) の日付範囲に含まれる

「1 日飛ばし」など、連続でない日付は上記 3 条件を満たす限り許容する (現実的なユースケース例: 月火に肉じゃが、
水木は別献立、金にまた肉じゃが → 金の行を月火の作り置きにまとめる)。

各メニュー項目の表示は行の作り置き状態に応じて出し分けられる:

- **「作り置きから外す」**: その行が **複数行の作り置きに属している** ときだけ表示。単独作り置きの行では
  外す対象が無いので表示しない
- **「この品を連続 N 日」**: その行が **単独作り置き (1 行のみ)** のときだけ表示。既に複数行の作り置きに
  属している行では、更に連続コピーする意味が無いので表示しない

#### Scenario: 作り置きから外すと起点日だけが残る

- **WHEN** 月・火・水曜・夕に同じ作り置きの「肉じゃが」が並んでいる状態で、火曜の行の `⋯ → 作り置きから外す`
  を選ぶ
- **THEN** 火曜と水曜の「肉じゃが」の行が削除される
- **AND** 月曜の「肉じゃが」だけが残り、その行は新しい単独作り置きに属する (元の作り置き ID とは異なる)

#### Scenario: 単独作り置きの行に対して外す操作は何もしない

- **WHEN** ある行が単独の作り置き (1 行のみ) に属している状態で、その行の `⋯ → 作り置きから外す` を選ぶ
- **THEN** その行はそのまま残り、`meal_plans` は変化しない

#### Scenario: 同一レシピの近い日付の作り置きにまとめる

- **WHEN** 「火曜・夕」に単独で割り当てた「肉じゃが」があり、「月曜・夕」に別の作り置きの「肉じゃが」がある
  状態で、「火曜・夕」の `⋯ → 他の作り置きにまとめる` から「月曜・夕」の作り置きを選ぶ
- **THEN** 火曜の「肉じゃが」が月曜の作り置きに移り、両行が同じ作り置きに属する

#### Scenario: まとめ候補は同じ slot・同じレシピ・±4 日以内だけを提示する

- **WHEN** ユーザーが `⋯ → 他の作り置きにまとめる` を開く
- **THEN** 候補は「同じ slot」「同じレシピ」「対象行から ±4 日以内」の 3 条件を全て満たす他の作り置きのみが
  表示される (別 slot、別レシピ、日付レンジ外の作り置きは候補から除外される)

#### Scenario: レシピが違う作り置きにはまとめられない

- **WHEN** 「火曜・夕」の「肉じゃが」に対して、「月曜・夕」に別レシピ (「みそ汁」) の作り置きしかない状態で
  `⋯ → 他の作り置きにまとめる` を開く
- **THEN** 「月曜・夕」の「みそ汁」の作り置きは候補に表示されない
- **AND** 候補が 1 つも無い場合は「まとめられる作り置きがない」旨のメッセージが表示される

#### Scenario: 日付レンジ外の作り置きにはまとめられない

- **WHEN** 「金曜・夕」の「肉じゃが」に対して、5 日以上前の同レシピ作り置きしかない状態で
  `⋯ → 他の作り置きにまとめる` を開く
- **THEN** 5 日以上前の作り置きは候補に表示されない (対象行から ±4 日以内の作り置きだけが候補になる)

#### Scenario: 1 日飛ばした同一レシピの行はまとめられる

- **WHEN** 月・火に同じ作り置きの「肉じゃが」があり、金にも単独で「肉じゃが」があり (水木は別献立の状態)、
  金の行の `⋯ → 他の作り置きにまとめる` から月火の作り置きを選ぶ
- **THEN** 金の「肉じゃが」が月火の作り置きに移り、月・火・金の 3 行が同じ作り置きに属する

#### Scenario: 単独作り置きの行には「作り置きから外す」項目が出ない

- **WHEN** ある行が単独の作り置き (1 行のみ) に属している状態で、その行の `⋯` メニューを開く
- **THEN** メニューに「作り置きから外す」項目は表示されない
  (作り置きに属しているのに 1 行だけなので、外す対象がない)

#### Scenario: 作り置きに属する行には「この品を連続 N 日」項目が出ない

- **WHEN** ある行が複数行の作り置きに属している状態で、その行の `⋯` メニューを開く
- **THEN** メニューに「この品を連続 N 日」サブメニューは表示されない
  (既に作り置きなので、更に連続コピーする用途がない)

### Requirement: 作り置きの視覚識別

システムは、複数行を含む作り置きを **共通の枠色** と **🔗 アイコン** で SHALL 識別可能にする。色は内部の
作り置き ID から決定的にローテーション (2〜3 色) される。同じ作り置きは常に同じ色、単独 (1 行のみ) の作り置きは
色を付けない。

#### Scenario: 2 つの作り置きが同時に存在すると別の色になる

- **WHEN** 表示中の週に 2 つの複数行の作り置きが存在する
- **THEN** 2 つの作り置きはそれぞれ異なる枠色で描画される

#### Scenario: 週をまたいで同じ作り置きが再表示されると同じ色

- **WHEN** 作り置き A を表示 → 別週へ移動 → 再度作り置き A のある週に戻る
- **THEN** 作り置き A の枠色は前回と同じ色で表示される (作り置き ID から決定的に導出される)

#### Scenario: 🔗 アイコンで複数行の作り置きを識別する

- **WHEN** ある行が複数行を含む作り置きに属している
- **THEN** その行の左端に 🔗 アイコンが表示される

## MODIFIED Requirements

### Requirement: 作り置きコピー (1 品単位)

システムは、1 品の作り置きコピーを SHALL 提供する。ユーザーは品行 `⋯ → この品を連続 N 日` から日数 (2 / 3 / 4 日)
を選び、次にコピー方法 (「作り置き」= 1 回分をまとめる、または「別調理」= N 回に分けて作る) を選ぶ。既定は
「作り置き」。コピー元の (日付, slot) を起点に連続する N 日分の同じ slot に、その 1 品を追加する。N には
起点日自身を含む。

#### Scenario: 空だった連続日に 1 品が入る

- **WHEN** 「月曜・夕」に「肉じゃが」1 品があり、火〜金・夕が空の状態でユーザーが `⋯ → 連続 3 日` を選ぶ
- **THEN** 「月曜・夕」「火曜・夕」「水曜・夕」の各 slot に「肉じゃが」が入り、木曜・夕と金曜・夕は空のままになる

#### Scenario: 空だった連続日に 1 品が入る (作り置き)

- **WHEN** 「月曜・夕」に「肉じゃが」1 品があり、火〜金・夕が空の状態でユーザーが `⋯ → 連続 3 日 → 作り置き` を選ぶ
- **THEN** 「月曜・夕」「火曜・夕」「水曜・夕」の各 slot に「肉じゃが」が入る
- **AND** 3 行はすべて同じ作り置きに属し、UI で共通枠色と 🔗 アイコンが表示される
- **AND** 「木曜・夕」「金曜・夕」は空のままになる

#### Scenario: 別調理を選ぶと各日が独立した作り置き

- **WHEN** 同じ状況で `⋯ → 連続 3 日 → 別調理` を選ぶ
- **THEN** 3 行はそれぞれ独立した作り置きに属し、UI で共通枠色は表示されない

#### Scenario: 起点自身の日にも重複追加しない

- **WHEN** 「月曜・夕」に「肉じゃが」1 品がある状態で `⋯ → 連続 3 日 → 作り置き` を選ぶ
- **THEN** 「月曜・夕」の「肉じゃが」は 1 品のままで、同じレシピが 2 回並ぶことはない
- **AND** 起点行の作り置き ID は、コピー元と共有される (作り置き選択時のみ)

### Requirement: 作り置きコピー (slot 全体)

システムは、slot 全体 (複数品) の作り置きコピーを SHALL 提供する。ユーザーは slot 右下 `⋯ → slot 全体を連続 N 日
コピー` から日数を選び、次にコピー方法 (「作り置き」= コピー元の全品ごとにコピー先 N 行が同一の作り置き、
「別調理」= 各日ごとに独立した作り置き) を選ぶ。既定は「作り置き」。

#### Scenario: 2 品構成を 3 日分コピーする

- **WHEN** 「月曜・夕」に「肉じゃが」「みそ汁」があり、火〜金・夕が空の状態でユーザーが slot 右下
  `⋯ → slot 全体を連続 3 日` を選ぶ
- **THEN** 「月曜・夕」「火曜・夕」「水曜・夕」の各 slot に「肉じゃが」「みそ汁」の 2 品が position 順で入る

#### Scenario: 2 品構成を 3 日分コピー (作り置き) するとレシピごとに 3 行が同じ作り置き

- **WHEN** 「月曜・夕」に「肉じゃが」「みそ汁」があり、火〜金・夕が空の状態でユーザーが slot 右下
  `⋯ → slot 全体を連続 3 日 → 作り置き` を選ぶ
- **THEN** 月・火・水曜・夕の「肉じゃが」3 行が 1 つの作り置きに属し、「みそ汁」3 行が別の 1 つの作り置きに属する
- **AND** 「肉じゃが」の作り置きと「みそ汁」の作り置きはそれぞれ異なる枠色で表示される

### Requirement: 作り置きコピー先の衝突解決

システムは、作り置きコピー先の (日付, slot) に既存の割当があるとき、ユーザーに「追加」「上書き」「キャンセル」の
選択を SHALL 求める。この選択はコピー方法 (「作り置き」/「別調理」) とは独立に組み合わせて適用される。「追加」は
コピー元品を既存品の末尾に append、「上書き」は既存 slot を空にしてから置き換え、「キャンセル」は割当を一切変更
しない。

#### Scenario: 追加を選ぶと元の品と併存する

- **WHEN** 「火曜・夕」に「豚汁」がある状態で「月曜・夕」の「肉じゃが」を連続 3 日でコピーし、「追加」を選ぶ
- **THEN** 「火曜・夕」は「豚汁」「肉じゃが」の 2 品構成になる

#### Scenario: 上書きを選ぶと既存 slot が置き換わる

- **WHEN** 同じ状況で「上書き」を選ぶ
- **THEN** 「火曜・夕」の既存 slot が全削除され、「肉じゃが」1 品だけになる

#### Scenario: 衝突がない場合はダイアログを出さない

- **WHEN** コピー先の (日付, slot) がすべて空である
- **THEN** 衝突解決ダイアログは表示されず、そのままコピーが実行される

#### Scenario: 追加 + 作り置きの組み合わせ

- **WHEN** 「火曜・夕」に「豚汁」がある状態で「月曜・夕」の「肉じゃが」を連続 3 日 × 作り置きでコピーし、「追加」
  を選ぶ
- **THEN** 「火曜・夕」は「豚汁」「肉じゃが」の 2 品構成になり、「肉じゃが」3 行は同一の作り置き、「豚汁」は
  それとは別の作り置きに属する

#### Scenario: 上書き + 別調理の組み合わせ

- **WHEN** 同じ状況で「上書き」+「別調理」を選ぶ
- **THEN** 「火曜・夕」の既存 slot が全消去され、「肉じゃが」1 品だけになる
- **AND** 火曜・水曜の「肉じゃが」はそれぞれ独立した作り置きに属する (共有扱いにはならない)

#### Scenario: キャンセルを選ぶと何も変わらない

- **WHEN** 同じ状況で「キャンセル」を選ぶ
- **THEN** 「月曜・夕」を含む全ての (日付, slot) は元の状態のまま維持される
- **AND** 作り置きの関係も一切変更されない
