## Purpose

利用者が自分で選んだ AI エージェントから、MCP を通して meal-cycle のデータを参照し、追加と状態の変更を行えるようにする capability。
アプリ自身は AI を持たず通信もしない。削除や書き換えはエージェントに開かない。

## ADDED Requirements

### Requirement: MCP サーバーの接続方式

システムは、GUI とは別の実行ファイルとして MCP サーバーを SHALL 提供する。
MCP サーバーは、AI クライアントが起動した子プロセスとして標準入出力だけでやり取りし、ネットワークの待ち受けも外部への通信も行わない。
MCP サーバーは、GUI が使うのと同じ OS 標準の場所のデータベースを開く。起動時の引数で別のデータベースのファイルを指せる。

#### Scenario: AI クライアントにツールの一覧を返す

- **WHEN** AI クライアントが MCP サーバーを起動し、ツールの一覧を求める
- **THEN** 参照、追加、状態の変更のツールが、それぞれの説明と入力の形とともに返る

#### Scenario: ネットワークの待ち受けをしない

- **WHEN** MCP サーバーを起動している
- **THEN** MCP サーバーのプロセスは、どのポートでも待ち受けていない

### Requirement: データベースの版の確認

MCP サーバーは、ツールを動かす前に、データベースのファイルがあることと、スキーマの版がこの MCP サーバーの版と一致することを SHALL 確かめる。
一致しないときは、ツールを動かさずに理由を返し、データベースを作ることも、スキーマを更新することも、控えを作ることもしない。
スキーマの更新と更新前の控えは、GUI の起動に任せる。

#### Scenario: データベースが無いときは GUI の起動を求める

- **WHEN** データベースのファイルが無い状態で、エージェントがツールを呼ぶ
- **THEN** ツールは失敗し、データベースが無いことを表すコードが返る
- **AND** データベースのファイルは作られない

#### Scenario: スキーマが古いときは GUI の起動を求める

- **WHEN** 古い版のスキーマのデータベースがある状態で、エージェントがツールを呼ぶ
- **THEN** ツールは失敗し、スキーマが古いことを表すコードが返る
- **AND** データベースのスキーマの版は変わらず、`backups` フォルダの中身も変わらない

#### Scenario: スキーマが新しいときは MCP サーバーの更新を求める

- **WHEN** MCP サーバーより新しい版のスキーマのデータベースがある状態で、エージェントがツールを呼ぶ
- **THEN** ツールは失敗し、スキーマが新しすぎることを表すコードが返る

### Requirement: データの参照

MCP サーバーは、次のデータを参照するツールを SHALL 提供する。
返す内容は、同じ時点で GUI の該当画面が表示する内容と一致する。

- レシピの一覧 (アーカイブしていないもの。ID、名前、人数、タグ) と、ID を指定した 1 件の詳細 (材料、手順、メモを含む)
- 開始日と週数 (1 / 2 / 4) を指定した期間の献立 (各品の ID、日付、時間帯、並び順、レシピ、作った印)
- 冷蔵庫の在庫 (量、単位、賞味期限、期限の状態)
- 常備品 (名前と、ある / 少ない / ない の状態)
- 開始日と日数を指定した買い物リスト
- 献立の候補 (使い切り / 久しぶりに / 時短 の 3 軸) と、週の開始日を指定した週の提案

#### Scenario: 期間の献立を返す

- **WHEN** 2026-11-02 の夕食に「肉じゃが」が割り当てられている状態で、エージェントが 2026-11-02 から 1 週間の献立を求める
- **THEN** 2026-11-02 の夕食に「肉じゃが」の品が 1 つ含まれた結果が返る

#### Scenario: 存在しないレシピの詳細を求めると失敗する

- **WHEN** エージェントが、存在しない ID のレシピの詳細を求める
- **THEN** ツールは失敗し、レシピが見つからないことを表すコードが返る

#### Scenario: 許されない週数では献立を返さない

- **WHEN** エージェントが週数 3 で期間の献立を求める
- **THEN** ツールは失敗し、週数が不正であることを表すコードが返る

### Requirement: 献立へのレシピの割り当て

MCP サーバーは、日付、時間帯 (朝食 / 昼食 / 夕食)、レシピの ID を指定して、献立に 1 品を足すツールを SHALL 提供する。
足した品は、その時間帯の既存の品の後ろに並ぶ。既存の品は置き換えない。

#### Scenario: 既存の品の後ろに足す

- **WHEN** 2026-11-02 の夕食に「肉じゃが」がある状態で、エージェントが同じ夕食に「味噌汁」を割り当てる
- **THEN** 2026-11-02 の夕食は「肉じゃが」「味噌汁」の順の 2 品になる
- **AND** 足した品の ID が返る

#### Scenario: 存在しないレシピは割り当てない

- **WHEN** エージェントが、存在しない ID のレシピを献立に割り当てる
- **THEN** ツールは失敗し、献立は変わらない

### Requirement: 在庫の追加

MCP サーバーは、食材名、量、単位、賞味期限を持つ在庫を 1 件以上まとめて冷蔵庫に足すツールを SHALL 提供する。
検証は S05 で追加するときと同じ規則で行い、1 件でも条件を満たさなければ 1 件も足さない。

#### Scenario: 複数の在庫をまとめて足す

- **WHEN** エージェントが「玉ねぎ 3 個」と「豚こま 300 g (賞味期限 2026-11-05)」を足す
- **THEN** 冷蔵庫の在庫に 2 件が増え、足した在庫が ID とともに返る

#### Scenario: 条件を満たさない在庫があれば何も足さない

- **WHEN** エージェントが「玉ねぎ 3 個」と、食材名が空の在庫を一緒に足す
- **THEN** ツールは失敗し、食材名が空であることを表すコードが返る
- **AND** 冷蔵庫の在庫は変わらない

### Requirement: 常備品の追加と状態の変更

MCP サーバーは、常備品を名前で 1 件足すツールと、常備品の状態を ある / 少ない / ない のいずれかに変えるツールを SHALL 提供する。
状態を「少ない」か「ない」にした常備品は、GUI で変えたときと同じく買い物リストに載る。

#### Scenario: 常備品を「ない」にすると買い物リストに載る

- **WHEN** 常備品「牛乳」が「ある」の状態で、エージェントが「牛乳」を「ない」に変える
- **THEN** 買い物リストを求めると、常備品の欄に「牛乳」が含まれる

#### Scenario: 同じ名前の常備品は足さない

- **WHEN** 常備品「牛乳」がある状態で、エージェントが「牛乳」を常備品に足す
- **THEN** ツールは失敗し、常備品が重複していることを表すコードが返る

### Requirement: レシピの登録

MCP サーバーは、名前、人数、タグ、材料、手順、メモを持つレシピを 1 件登録するツールを SHALL 提供する。
検証は S04 で登録するときと同じ規則で行う。

#### Scenario: レシピを登録すると一覧に出る

- **WHEN** エージェントが名前「豚汁」、人数 2、材料「豚こま 100 g」でレシピを登録する
- **THEN** 登録したレシピが ID とともに返る
- **AND** レシピの一覧に「豚汁」が含まれる

### Requirement: エージェントに公開しない操作

MCP サーバーは、データを消す操作と、既存のデータを書き換える操作 (常備品の状態の変更を除く) を SHALL NOT 提供する。
対象は、献立の品の削除と時間帯を空にすること、品の差し替えと移動と並べ替え、作った印と在庫の消費、作り置きを広げる操作、
在庫とレシピの編集と削除、常備品の削除、設定の変更、レシピの書き出しと取り込み、データベースの書き出しと復元である。

#### Scenario: ツールの一覧に削除の操作が無い

- **WHEN** AI クライアントがツールの一覧を求める
- **THEN** 献立、在庫、常備品、レシピのいずれについても、削除と編集のツールは含まれない

### Requirement: ツールの失敗の返し方

MCP サーバーは、ツールが失敗したとき、失敗の種類を表すコードと英語の短い説明を、ツールの失敗として SHALL 返す。
入力の形が不正なとき (必須の項目が無い、日付の書式が違う) も、同じ形で返す。
失敗したツールは、データベースに何も書き込まない。

#### Scenario: 日付の書式が違えば失敗のコードを返す

- **WHEN** エージェントが日付「11/2」で献立にレシピを割り当てる
- **THEN** ツールは失敗し、日付が不正であることを表すコードと説明が返る
- **AND** 献立は変わらない

### Requirement: 設定の反映

MCP サーバーは、ツールを呼ばれるたびに、S09 で保存されている設定値を読んで SHALL 動かす。
GUI で設定を変えたあとは、MCP サーバーを起動し直さなくても、変えた値で買い物リストや在庫の期限の状態を返す。

#### Scenario: GUI で変えた期限の閾値が在庫の状態に反映される

- **WHEN** MCP サーバーが起動している間に、GUI の S09 で 🔴 の日数を変えて保存し、そのあとエージェントが在庫を求める
- **THEN** 返る在庫の期限の状態は、変えたあとの日数で判定されている

### Requirement: GUI へのエージェントの書き込みの反映

GUI は、ウィンドウにフォーカスが戻ったとき、表示中の画面のデータを SHALL 取り直す。
エージェントが MCP サーバーを通して書き込んだ内容は、GUI を開き直さずに、ウィンドウに戻った時点で表示に出る。

#### Scenario: ウィンドウに戻ると割り当てた献立が表示される

- **WHEN** GUI で S01 を表示したまま別のウィンドウに切り替え、エージェントが表示中の期間の夕食にレシピを割り当てたあと、GUI のウィンドウに戻る
- **THEN** S01 の該当する夕食のセルに、割り当てたレシピが表示される
