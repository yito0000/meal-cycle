## Context

動機は proposal.md の Why を参照。

- S01 は表示中の期間の献立を `MealPlanService.ListPeriod` で取得済みで、行は日付、時間帯、セル内の順 (`position`) を持つ
- S07 の「テキストでコピー」は `shopping-text.ts` の純関数で文字列を組み、`navigator.clipboard.writeText` で書き、件数を通知で知らせる (add-shopping-copy-text)
- 日付の表示は `@/lib/format-date` の `formatDisplayDate` (月/日(曜)) を使っている
- S01 の時間帯表示 (夕食のみ / 3 食) は表示の切替で、S07 への導線は表示に関係なく全時間帯を対象にしている

## Goals / Non-Goals

**Goals:**

- S01 の献立を、受け取った家族がそのまま読める短いテキストで渡せるようにする
- S07 のコピーと見た目と操作をそろえる

**Non-Goals:**

- 範囲や書式の選択 (proposal.md の Non-goals)

## Decisions

### D1. 文字列はフロントの純関数で組む

`mealplan-text.ts` に `buildMealPlanText(entries, period, t)` を置き、`{ text, dayCount }` を返す。

**選択肢:**

- (a) Go のサービスにテキストを返すメソッドを足す — Pros: MCP などほかの入口でも使える /
  Cons: 文言 (見出し、時間帯の略称) を Go に持つことになり、design.md §7 の「Go は日本語を持たない」に反する
- (b) フロントの純関数で組む ← 採用 — Pros: S07 のコピーと同じ構成。i18n の文言で組める。取得済みのデータで足りる /
  Cons: 期間の献立を別の画面から渡すときは同じ関数を呼ぶ必要がある

**採用: (b)**。理由: 文言の置き場所の方針と、S07 のコピーとの一貫性を優先する。

### D2. 時間帯表示にかかわらず全時間帯を含める

**選択肢:**

- (a) 表示中の時間帯だけを含める — Pros: 画面に見えているものと同じになる /
  Cons: 「夕食のみ」の表示で昼食の予定があると、家族に渡す献立から黙って抜け落ちる
- (b) 全時間帯を含める ← 採用 — Pros: S07 への導線と同じ扱い。抜け落ちが無い / Cons: 画面に見えていない行がテキストに入る

**採用: (b)**。理由: 渡した側も受け取った側も、抜け落ちに気付く手段が無い。見えていない行が入るほうは、テキストを読めば分かる。

### D3. 書式

```
献立 11/2(月)〜11/8(日)
11/2(月) 夕: 肉じゃが、味噌汁
11/3(火) 昼: サンドイッチ
11/3(火) 夕: カレー
```

- 1 行 = 1 つの `(date, meal)`。日付の昇順、同じ日は朝、昼、夕の順。品はセル内の順に「、」で区切る
- 時間帯は「朝」「昼」「夕」の略称にする (i18n の key `pages.mealPlan.copy.meal_breakfast` など)。英語は `B` / `L` / `D` ではなく `Breakfast` などにする
- 献立の無い `(date, meal)` は行を出さない。空の日を「未定」と書くと、夕食のみの家庭で朝と昼の「未定」が並んで読みにくい
- 通知は「N 日分の献立をコピーしました」。数えるのは行のある日付の数

**選択肢 (日付の見出しを別行にするか):**

- (a) 日付を見出し行にして、時間帯ごとに箇条書きにする — Pros: 3 食の家庭で読みやすい / Cons: 夕食のみの家庭で行数が倍になる
- (b) 日付と時間帯を 1 行にまとめる ← 採用 — Pros: 夕食のみの既定で短い。メッセージアプリの 1 画面に 1 週間が収まる / Cons: 3 食では日付が 3 回繰り返す

**採用: (b)**。理由: 既定の利用 (夕食のみ) で短いほうを選ぶ。

### D4. 削除済みレシピと作った印

削除済みレシピの品も S01 に残っているので、レシピ名のまま含める。作った印と作り置きは家族が献立を読むのに要らないので含めない。

## Risks / Trade-offs

- [Risk] クリップボードへの書き込みが webview で拒否される → S07 のコピーと同じく失敗を通知で知らせる。S07 で動いている経路なので新しい失敗の種類は無い
- [Risk] 4 週表示で 28 日分をコピーすると長い → 表示中の期間がそのまま範囲なので、利用者は 1 週表示にしてからコピーすればよい。注記は出さない
