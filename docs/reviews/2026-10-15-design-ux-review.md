## 優先度高：動作の不具合

### R36. 期間をまたぐ作り置きが、S01 では単独の品として扱われる（再現済み）

- [ ] 対応済み

日曜の夕食から月曜の夕食へ作り置きを広げ、日曜を含む週を表示すると、日曜の行の `batchMemberCount` が 1 になる。
`MealPlanRepo.ListPeriod` は件数を `COUNT(*) OVER (PARTITION BY m.batch_id)` で数えているが、ウィンドウ関数は `WHERE` で期間に絞った後の行にしか掛からない。
関数のコメントは「期間外の行も PARTITION に加算されるのが仕様」としているが、実際の挙動は逆である。

S01 は件数が 2 以上かどうかで作り置きを判定しているので、期間の端の行では次のことが起きる。

- 枠色が付かず、作り置きに属していることが見えない
- `draggable` になり、作り置きの行を 1 行だけ D&D で動かせる（spec が禁じている操作）
- 品のメニューに「作り置きをやめる」が出ない
- 期間内に 2 行以上あっても、確認ダイアログが示す「削除される行の数」は期間内の行しか数えない。
  `DissolveBatchDialog` のコメントは「表示中の期間外の行も消す」ことを理由に事前確認を選んでおり、その確認の数字が実際より少なくなる

S07 の `loadPlannedGroups` は相関サブクエリで全期間の行を数えており、正しい件数を返している。
`ListPeriod` も同じ書き方に揃え、「期間の外に続く作り置きの件数」のテストを足せば直る。
proposal を通さない不具合修正の大きさである。

### R37. 「作り置きを広げる」の上書きが、表示期間の外のセルを警告なしに消す

- [ ] 対応済み

統合ダイアログは、既に品が入っているセルを薄い黄色で示す。
この判定は S01 が持っている `entries`（表示中の期間の行）だけを見ているので、期間の外の日は品があっても黄色にならない。
1 週表示で土曜から広げると、格子の 4 行（土曜から火曜）のうち月曜と火曜は翌週に当たり、品の有無が格子に出ない。

この状態で「衝突: 上書き」を選ぶと、`MealPlanRepo.Spread` は対象セルの既存の品を消してから入れる。
消した品は戻せない。
前回の R30 で品の削除と時間帯全体のクリアには「元に戻す」が付いたが、上書きはその対象から外れたままである。
上書きで消える品には、別の作り置きの行や「作った」印の付いた行も含まれうる。

直し方は 2 つある。

- ダイアログを開くときに、格子の範囲（起点日から 3 日後まで）の行を別に取得し、黄色の判定に使う
- `SpreadEntry` が上書きで消した行を返し、品の削除と同じ「元に戻す」を出す

前者は警告の欠落を、後者は取り返しのつかなさを直す。
両方を入れるのが望ましいが、どちらか 1 つなら後者を選ぶ（期間の内側の上書きも救えるため）。
spec の振る舞いが変わるので proposal を通す。

### R38. 同じ日の昼と夕にまたがる作り置きで、「作り置きをやめる」が夕食の行を残すことがある（再現済み）

- [ ] 対応済み

再現した手順は次のとおり。

1. 月曜の昼食に B、A の順で割り当てる（A は position 1）
2. A を月曜の夕食へ広げる（夕食の A は position 0）
3. 昼食の A で「作り置きをやめる」を選ぶ

残るのは夕食の A で、昼食の A が消える。
`SplitBatch` は残す行を `ORDER BY date, position` で選んでおり、時間帯の順を見ていない。
前回の R23 で `ListMergeCandidates` には朝昼夕の順を足したが、同じ並べ方が `SplitBatch` には入っていない。
spec と product.md の説明（作り置きの最初の日の行だけを残す）は、同じ日の中の順を決めていない。
spec に「最初の日の、いちばん早い時間帯の行」と書き足し、`SplitBatch` の並びに時間帯の順を足す。

## 設計

### R39. 起点と同じ日の、起点より前の時間帯にも広げられる

- [ ] 対応済み

`ValidateSpreadTargets` は「起点日より前の日付」だけを弾き、同じ日の朝食と昼食は通す。
統合ダイアログの格子も、夕食が起点のときに同じ日の朝食と昼食にチェックを付けられる。
コメントと design.md は「作り置きは翌日以降に伸ばす操作」と説明しており、夕食に作ったものを同じ日の昼に食べる指定は、その説明と合わない。
R38 の逆転も、この経路で作った作り置きで起きやすい。

弁当用に朝作って昼に回す使い方は考えられるので、禁止するかどうかは利用者が決めることである。
禁止するなら、起点より前の時間帯を格子で選べないようにし、検証にも足す。
許すなら、コメントと spec の「翌日以降」という説明を「起点より後のセル」に改める。

### R40. 広げる操作とコピーで、削除済みレシピの行が増える

- [ ] 対応済み

recipe の spec は、削除済みレシピを「献立への新たな割当と、既存の品の入替」から除くとしている。
`Assign` と `Replace` は `ensureActiveRecipe` で確かめるが、`Spread` と `CopyLeftover` は確かめない。
削除済みレシピの品を S01 で「作り置きを広げる」と、そのレシピの行が新しく増える。
S01 の `Entry` は削除済みかどうかを持たないので、利用者は画面上でそのことに気づけない。

広げる操作を「新たな割当」に数えるかは spec に書かれていない。
数えるなら `Spread` と `CopyLeftover` に `ensureActiveRecipe` を足し、数えないなら spec の除外範囲にその旨を書く。

### R41. レシピの材料の量を Go 側で検証していない

- [x] 対応済み（proposal: fix-recipe-amount-validation）

`validateRecipeInput` は材料の名前だけを検証し、量は見ていない。
S04 の量の欄は `type="number" min={0}` だが、`min` は入力を止めないので `-1` を打てば保存される。
冷蔵庫の在庫（`validateStockInput`）とインポート（`ParseAmount`）は負の値を弾いており、手入力の経路だけが抜けている。
負の量は S07 の合算で必要量を減らす方向に効く。
`validateRecipeInput` に「0 以上、上限以下」の検証を足し、S04 の `validate` にも同じ規則を入れる。

### R27 の残り：エラーの受け渡しが文字列の部分一致に頼っている

前回の R27 の 2 点目はそのまま残っている。
あわせて、`error-messages.ts` のコメント（`MergeBatch` だけが `ErrEntryNotFound` を別の意味で返す）は、`ErrBatchTargetNotFound` が分かれた今では古い。

## UI/UX

### R42. 統合ダイアログの日付が `2026-10-19` の形で出る

- [ ] 対応済み

統合ダイアログの説明文（「起点: 2026-10-19 夕食 肉じゃが」）は、日付を ISO 形式のまま差し込んでいる。
格子の行見出しは `10/19(月)` の形に整えているので、同じダイアログの中で表記が揃っていない。
チェックボックスの読み上げラベルも同じ ISO 形式である。
行見出しと同じ `Intl.DateTimeFormat` を説明文とラベルにも使う。

### R43. 「作った」チェックボックスのラベルがどの品でも同じ

- [ ] 対応済み

品行のチェックボックスの `aria-label` は「作った」だけで、レシピ名を含まない。
セルに 3 品あると、読み上げでは「作った」が 3 つ並び、どの品の印かわからない。
「肉じゃがを作った」のようにレシピ名を入れる。

## テスト

### R44. skip している E2E の多くは、skip の理由がもう成り立たない

- [ ] 対応済み

`mealplan-batch.spec.ts` に 13 件、`mealplan-assign.spec.ts` に 7 件の `test.skip` が残っている（前回は 27 件）。
14 件の skip 理由は「Radix DropdownMenu の Portal 操作に対応したら有効化する」である。
しかし `helpers.ts` には品のメニューを開いて項目を選ぶ手順が既にあり、8 つの spec ファイルがそれを使っている。
入替、削除、時間帯全体のクリア、まとめる操作、枠色のシナリオは、既存の手順の組み合わせで有効にできる見込みが高い。

D&D の 6 件は「Playwright の drag はイベントを確実に発火させない」を理由にしている。
`DataTransfer` を作って `dragstart`、`dragover`、`drop` を `dispatchEvent` で順に送る形なら、HTML5 D&D のハンドラは通せることが多い。
R36 の「作り置きの行はドラッグできない」は、まさにこの skip の範囲で起きている。

あわせて、spec のシナリオ名「作り置**み**に属する行はドラッグできない」に誤字がある。
シナリオ名と E2E のテスト名を同じコミットで直す。
