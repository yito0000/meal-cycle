# レシピのインポート形式

料理サイトのレシピを集めるとき、ページを AI に読ませれば決まった形式のテキストにはすぐ変換できる。
meal-cycle は外部と通信しないので、ページの取得と変換はアプリの外で行い、アプリは変換済みのファイルを読んで登録するところだけを受け持つ。
この文書は、そのファイルの形式と、AI に変換させるときのプロンプトのひな形をまとめたものである。

読み込みは S02 レシピ一覧の「インポート」ボタンから行う（[product.md §4 S02](product.md)、ワイヤーは [S02a](wireframes/S02a_recipe_import_dialog.drawio.svg)）。
「ファイルを選ぶ」で Markdown ファイルを 1 つ以上選ぶか、「フォルダを選ぶ」でフォルダごと読み込む。
フォルダを選んだときは、下位のフォルダも含めて拡張子 `.md` のファイルだけを読み、ほかのファイルは黙って飛ばす。
一度に読めるのは 100 件まで、1 ファイルは 64 KB までである。

## ファイルの構成

1 つのファイルが 1 件のレシピになる。
ファイルの先頭に `---` の行で囲んだ YAML の **frontmatter** を置き、その後ろの本文に手順とメモを書く。

### frontmatter の項目

- **name**：レシピ名。必須で、200 字まで
- **servings**：人数。1〜99 の整数。省略すると 2 人分として読む
- **tags**：タグの配列。1 つ 30 字まで。省略できる
- **ingredients**：材料の配列。省略できる。各要素は次の 3 つを持つ
  - **name**：材料名。必須
  - **amount**：量。書き方は後述する。省略すると量 0
  - **unit**：単位。省略できる

上記以外の項目（`source` や `cookTime` など）は読まずに無視する。

### 本文の節

本文は、行頭が `## ` のレベル 2 の見出しで区切って読む。
「## 手順」（または「## Steps」）の節が手順に、「## メモ」（または「## Notes」）の節がメモになる。
英字の見出しは大文字と小文字を区別しない。

節の中身は Markdown のまま保存され、S03 レシピ詳細で描画される。
`### コツ` のようなレベル 3 以下の見出しは、節の区切りにはならず中身として残る。
どちらの見出しも無い本文は、全体を手順として読む。
見出しがあるときは、最初の見出しより前に書いた文と、手順とメモ以外の見出しの節は読まない。

元レシピの URL を残したいときは、メモの節に書く。
レシピに URL 専用の欄は無い。

### 量の書き方

`amount` には数値をそのまま書くのがいちばん確実である。
とはいえ、AI の出力も人の手書きも「1/2」や「大さじ2」のように揺れるので、よく見る書き方はアプリ側で量と単位に直して読む。

| 書き方 | 読んだ結果 |
| --- | --- |
| `2`、`0.5` | そのまま量にする |
| `１．５`、`１／２`（全角） | 半角として読む |
| `1/2`、`1/3` | 小数に直す（小数第 2 位で丸めるので `1/3` は 0.33） |
| `1と1/2`、`1 1/2` | 帯分数として 1.5 |
| `2〜3`、`2~3`、`2-3` | 大きいほうの 3 |
| `大さじ2`（unit なし） | 量 2、単位「大さじ」 |
| `3個`（unit なし） | 量 3、単位「個」 |
| `少々`、`適量`、`適宜`、`少量`、`ひとつまみ`、`お好みで` | 量 0、その言葉を単位にする（unit があれば unit を優先） |

範囲で大きいほうを取るのは、買い物リストで材料が足りなくなる側を避けるためである。
「大さじ」「小さじ」「カップ」は前に付く単位として、それ以外は数値の後ろに付く単位として読む。

数値に付いた単位と `unit` が食い違う書き方（`amount: "3個"` と `unit: "本"`）や、前後の両方に単位が付いた書き方（`大さじ2杯`）は、どちらを信じるか決められないのでエラーになる。
どの書き方にも当たらない量（`たくさん`、`半分` など）もエラーになり、インポートダイアログに材料名を添えて理由が出る。

## 1 ファイルの例

```markdown
---
name: "肉じゃが"
servings: 3
tags: ["和食", "煮物"]
ingredients:
  - name: "じゃがいも"
    amount: 3
    unit: "個"
  - name: "牛こま切れ肉"
    amount: 200
    unit: "g"
  - name: "玉ねぎ"
    amount: "1/2"
    unit: "個"
  - name: "醤油"
    amount: 2
    unit: "大さじ"
  - name: "砂糖"
    amount: 1
    unit: "大さじ"
  - name: "塩"
    amount: "少々"
---

## 手順

1. じゃがいもは皮をむいて一口大に切り、水にさらす。
2. 鍋で牛肉と玉ねぎを炒め、じゃがいもを加える。
3. 水と調味料を入れ、落としぶたをして 15 分煮る。

### コツ

煮汁が少なくなったら鍋をゆすって全体にからめる。

## メモ

出典: https://example.com/recipes/nikujaga
```

## 取り込むまでの流れ

ファイルを選ぶと、アプリはファイルごとに形式と入力制約を確かめ、結果をインポートダイアログ（S02a）に出す。
この時点ではまだ何も登録されない。

読めたファイルが 1 つなら、S03 と同じ表記のプレビューが出る。
2 つ以上なら 1 ファイル 1 行の一覧になり、取り込む行をチェックで選ぶ。
エラーのあるファイルは選べない。
登録済みのレシピや、同時に読んだ別のファイルと名前が同じレシピには「同名あり」が付き、既定ではチェックが外れる。
名前は前後の空白を除いて完全一致で比べるので、「肉じゃが」と「肉ジャガ」は別の名前として扱う。
同名ありでもチェックを入れれば取り込め、既存のレシピは上書きされず別のレシピとして追加される。

「取り込む」を押すと、選んだレシピを 1 回でまとめて登録する。
途中で失敗したときは 1 件も登録されないので、そのまま選び直して取り込み直せばよい。
ダイアログの中では内容を直せないため、直したいときは元のファイルを直して選び直すか、取り込んだあとに S04 で編集する。

## AI 向けのプロンプトのひな形

料理サイトのページを AI に読ませるときは、次のプロンプトに URL かページの本文を添えて渡す。
YAML は、コロンや `#` を含む値を引用符で囲まないと読めなくなる。
プロンプトで文字列の値を必ず引用符で囲ませているのは、それを避けるためである。

````text
次のレシピを、下の形式の Markdown ファイルに変換してください。

# 出力の規則

- 1 レシピにつき 1 ファイルで出力する。複数のレシピがあるときは、ファイルごとにコードブロックを分け、ファイル名 (英小文字とハイフン、拡張子 .md) を添える
- ファイルの先頭に --- で囲んだ YAML の frontmatter を置く
- frontmatter の文字列の値は、必ずダブルクォートで囲む
- frontmatter に書く項目は name / servings / tags / ingredients だけにする
- servings は整数で書く。「作りやすい分量」など人数がわからないときは servings を書かない
- ingredients の各要素は name / amount / unit を持つ
  - amount は数値で書き、単位は unit に分けて書く (例: amount: 2, unit: "大さじ")
  - 分数は小数に直す (1/2 → 0.5)
  - 「少々」「適量」のように量を持たないものは amount を書かず、unit にその言葉を書く
- 本文には「## 手順」と「## メモ」の 2 つの節だけを書く
  - 手順は番号付きの箇条書きにする
  - 元のページの URL を「## メモ」の節に「出典: <URL>」の形で書く
  - コツや保存方法など、手順以外の補足もメモの節に書く
- 材料の見出し (「A」「合わせ調味料」など) は材料名に含めない

```markdown

name: "肉じゃが"

tags: ["和食"]

2. 鍋で煮る。

## メモ

出典: https://example.com/recipes/nikujaga
```
````
